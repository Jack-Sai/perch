# Perch

> Графический лаунчер и сторож времени выполнения для нативного `llama-server` (llama.cpp) в стиле macOS для Windows.

[中文](README.md) · [English](README.en.md) · [日本語](README.ja.md) · [한국어](README.ko.md)

Perch не включает и не распространяет llama.cpp. Достаточно указать свой `llama-server.exe` и модель GGUF, чтобы получить управление параметрами, запуск в один клик, мониторинг в реальном времени, диагностику сбоев и работу в трее.

## Возможности

- **Определение бинарника**: выберите exe или каталог release; Perch определит бэкенд CPU / CUDA / Vulkan / SYCL и версию, просканирует `--help`, построит форму параметров и закэширует результат.
- **Несколько профилей**: для каждой модели сохраняются host/port/`-ngl`/потоки/контекст/доп. аргументы/переменные среды/рабочий каталог; импорт и экспорт TOML (с маскированием пути к модели).
- **Рекомендации**: разбор метаданных GGUF (архитектура, квантование, обученный контекст, число слоёв) и объёма VRAM для предложения `-ngl`, `-c`, `-t` и `--flash-attn` в один клик.
- **Надёжный запуск**: без окна консоли; успех только после прохождения `/health`. Сбои классифицируются: занятый порт, нехватка VRAM, повреждённая модель, неверный аргумент, недостаточно прав и др.
- **Мониторинг**: CPU, рабочий набор, загрузка GPU, VRAM и температура с настраиваемыми порогами; экспорт CSV / JSON.
- **Журналы**: отдельный файл на сеанс, просмотр/копирование/экспорт, автоочистка устаревших записей.
- **Трей**: меню с учётом состояния — запуск/остановка, смена профиля, открытие Web UI; закрытие окна в трей.
- **Один экземпляр**: повторный запуск активирует существующее окно, а не создаёт второй демон.
- **Локальный API только для чтения**: `GET /status`, `/metrics`, `/profiles`, только на `127.0.0.1`, опциональный Bearer-токен.
- **CLI**: `status` / `start` / `stop` / `export`.
- **Интерфейс на китайском и английском**, светлая / тёмная / системная тема.

## Требования

- Windows 11 x64 (ожидаемо работает на Windows 10 21H2+)
- Ваш `llama-server.exe` (официальный release llama.cpp или своя сборка)
- Модель GGUF
- Для сборки: Node.js 22+, pnpm 10+, Rust 1.80+, Visual Studio C++ Build Tools

## Быстрый старт

1. Скачайте `Perch_x.y.z_x64-setup.exe` из Releases и установите.
2. При первом запуске выберите `llama-server.exe` (или распакованный каталог llama.cpp) и модель GGUF.
3. Проверьте порт и число слоёв GPU в разделе **Параметры запуска** и нажмите **Запустить**.
4. Когда статус станет **Работает**, нажмите **Открыть Web UI** и перейдите на `http://127.0.0.1:<порт>`.

> Сборка не подписана: при первом запуске SmartScreen может показать предупреждение. Выберите **Подробнее → Выполнить в любом случае**. Скачивайте только из Releases этого репозитория.

## Использование

### Параметры запуска

Основные параметры задаются формой. **Дополнительные** создаются из `llama-server --help`, поддерживают поиск и избранное. Предпросмотр команды предупреждает о дублях и переопределениях. Экспорт в `.bat` позволяет запускать без Perch.

### Профили

Один профиль — одна модель и один набор параметров. Импортированные профили с совпадающими именами переименовываются автоматически. Маскированный экспорт заменяет путь к модели заполнителем.

### Мониторинг и диагностика

Панель по умолчанию опрашивает данные раз в секунду и хранит 5 минут. Данные GPU берутся из `nvidia-smi`; без NVIDIA GPU включается режим CPU. При сбое показываются диагноз, полная командная строка и хвост журнала.

### Трей и завершение

Закрытие окна по умолчанию скрывает Perch в трей (настраивается). При выходе можно оставить llama-server запущенным.

## CLI

```powershell
perch.exe --cli status
perch.exe --cli start [--profile <имя>]
perch.exe --cli stop
perch.exe --cli export <каталог>
```

`status/start/stop` общаются с запущенным GUI через именованный канал; `start` при необходимости пытается запустить GUI. Вывод — JSON. `export` работает офлайн и экспортирует конфигурацию, кэш справки и журналы.

## Локальный API только для чтения

Включите в настройках и выберите порт (по умолчанию `3999`, только `127.0.0.1`). Если задан токен, добавляйте:

```http
Authorization: Bearer <token>
```

```powershell
curl.exe http://127.0.0.1:3999/status -H "Authorization: Bearer <token>"
curl.exe http://127.0.0.1:3999/metrics -H "Authorization: Bearer <token>"
curl.exe http://127.0.0.1:3999/profiles -H "Authorization: Bearer <token>"
```

Значения переменных среды в `/profiles` маскируются.

## Данные и конфиденциальность

- Конфигурация: `%USERPROFILE%\.perch\config.toml`
- Кэш справки: `%USERPROFILE%\.perch\help_cache.json`
- Журналы: `%USERPROFILE%\.perch\logs\server_<timestamp>.log`
- Все данные хранятся локально. Perch не отправляет телеметрию и не обращается к облаку.

## Сторонние зависимости и лицензии

Основные зависимости (полные списки в `src-tauri/Cargo.lock` и `pnpm-lock.yaml`):

| Зависимость | Назначение | Лицензия |
| --- | --- | --- |
| Tauri 2 / tauri-plugin-* | Оболочка, диалоги, уведомления, автозапуск, ссылки | MIT / Apache-2.0 |
| axum / tokio | Локальный API только для чтения | MIT |
| serde / serde_json / toml | Конфигурация и сериализация | MIT / Apache-2.0 |
| sysinfo | Мониторинг процессов и памяти | MIT |
| windows-sys | Win32 API (именованный канал, мьютекс, консоль) | MIT / Apache-2.0 |
| React / Vite | Фронтенд | MIT |
| Tailwind CSS | Стили | MIT |
| Recharts | Графики | MIT |
| lucide-react | Иконки | ISC |

Данные GPU читаются через системный `nvidia-smi`; Perch не статически линкует NVML и не поставляет компоненты NVIDIA. llama.cpp и модели не входят в проект; соблюдайте их лицензии.
